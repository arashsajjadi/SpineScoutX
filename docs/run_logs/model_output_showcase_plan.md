# Model-output showcase — plan + critique

> Research-only · not diagnostic · not clinically validated · not for medical
> decision-making. This sprint makes the **actual model outputs** visible, without
> reducing scientific honesty.

## What is currently missing
The README has performance **charts** but never shows what the model **outputs**: there is
no visible study-level finding graph, no case card, no per-level/per-condition severity
estimate with confidence, no review_required reasoning, no view-route indicator, and no
failure example. A chart is not an output. A visitor cannot see *what comes out*.

## What "real model output" must mean here
A study-level **research finding graph** generated by running the **deployable graders** on
**locked-test** cases — deterministic and traceable to source predictions:
- per (condition, level, side): severity estimate = argmax of the real softmax,
  P(normal_mild/moderate/severe), calibrated confidence, uncertainty flag, `review_required`
  with reasons derived from real signals (low confidence, high entropy, **model
  disagreement** between the router grader and its comparison grader, **axial level-scorer
  uncertainty** for subarticular, near-severe threshold);
- view route (sagittal-T2 canal / sagittal-T1 foraminal / axial-T2 subarticular) and crop
  provenance (auto / oracle / blocked);
- a study-level summary (max P(severe), findings needing review, high/low-confidence counts).
No field is invented; nulls are used where a signal is not computed.

## Data safety / privacy / license decision
**Committed visual cards render the structured finding graph (severity/probability bars,
flags, route badges) as matplotlib panels — NOT raw DICOM pixels.** This is the honest
"model output" (it *is* the output), and it carries no patient pixels, no DICOM metadata,
no identifiers. Cases are keyed by `case_id = sha1(study_id)[:10]` (study_ids are already
de-identified RSNA IDs; we hash anyway). The held-out reference severity is shown only as a
clearly-labelled `reference_label` (research target, not a model input/output) so failure
cases are visible. No raw MRI screenshots are committed.

## Artifacts to generate
- `reporting/finding_graph_schema.py` — formal schema + builder + validator + MD renderer.
- `scripts/make_model_output_showcase.py` — curated locked-test cases → JSON + MD + PNG cards.
- Committed safe cards under `docs/assets/showcase/`; full pack under
  `outputs/real/showcase_reports/` (gitignored).
- `docs/gallery.md` (incl. failure/uncertainty examples), output-first `README.md`,
  `docs/model_card.md` update, `docs/trust_and_limitations.md`.
- Tests: schema validation, no-diagnosis-wording, no-identifier, MD-reflects-JSON,
  review-reasons-consistency, probabilities sum≈1, every finding has provenance, and an
  **intelligence audit** (severity=argmax, route matches condition, probs match source).

## Constraints
Research-only; no diagnosis/treatment wording; no DICOM/identifiers/weights/runs committed;
no GT coordinates at auto inference (reference labels are held-out targets, clearly tagged).

## Skipped (with reason)
- **Raw DICOM screenshots** — privacy/license risk; structured cards are safer and *are* the
  output.
- **New training sprint** (Phase 7) — right-foraminal specialist was non-decisive and the
  axial level scorer is the known limiter; a better scorer is real work, documented as the
  next step rather than rushed here.
